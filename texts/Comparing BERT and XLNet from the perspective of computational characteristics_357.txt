Comparing BERT and XLNet from the Perspective of Computational
Characteristics
Hailong Li, Jaewan Choi, Sunjung Lee, Jung Ho Ahn
Department of Transdisciplinary Studies, Seoul National University
{lhl2017,cjw9202,shiish,ga jh}@sn u.ac.kr
Abstract
Exploiting attention mechanism, Transformer provides su-
perior performance compared to traditional CNN and RNN
models on various NLP (Natural Language Processing) tasks.
BERT and XLNet are two popular models utilizing Trans-
former . In this paper , we compare the computational char-
acteristics of the inference of BERT and XLNet using MPRC
(Microsoft Research Paraphrase Corpus), one of the popular
language understanding benchmarks. Through evaluation, we
observe that the both models exhibit similar computationalcharacteristics except the target-position-aware representa-
tion and relative position encoding features of XLNet, leading
to a better benchmark score at the cost of 1.2 ×arithmetic
operations and 1.5 ×execution time on a modern CPU.
Keywords: Deep learning, NLP , BERT, XLNet
1. Introduction
Recently, Transformer [6], which is based solely on attention
mechanism, shows superior performance in training time and
accuracy compared to CNN and RNN on various NLP (Natural
Language Processing) tasks.
Auto-encoding (AE) and auto-regressive (AR) language
modeling have been mainly used in the Transformer-based
language model. AE language model predicts the target word
by using bidirectional information for training. It is useful for
context understanding tasks. A notable example is BERT [2],
which was the forerunner in accuracy. AR language model is
trained to use only unidirectional information. The model is
adequate for text generation, but it is not effective in context
understanding tasks. XLNet [ 8], a generalized AR language
model, takes the pros of AE, whereas alleviating the cons of
AR, leading to a better accuracy compared to BERT.
Although BERT and XLNet are representative models on
various NLP benchmarks, they take a long time and require
considerable operations to perform both training and inference.
For example, training of BERT-large was performed on 64
TPUv3 chips for 4 days [ 2]. XLNet-large on 512 TPUv3 chips
took 2.5 days during training [ 8]. Inference of BERT-large and
XLNet-large with a single batch was performed respectively
on 1 GPU Titan V V olta for 22 iterations and 19 iterations
per second. In this paper, we analyze and compare the latest
language models, BERT and XLNet, through examining the
computational characteristics and memory bandwidth require-
ment during inference.x

2. Analyzing BERT
BERT is a popular attention-based Transformer language
model and auto-encoding model. It is a multi-layered stacked
structure using the encoder side of Transformer for mapping
input words to a sequence of vectors. The output of each
encoder reﬂects the correlation between the words for con-
centrating on important information. The encoder uses a self-
attention layer as a unit structure. As shown in Figure 1, it
calculates the ﬁnal attention output by using a query/key/value
(feature), which is obtained by matrix multiplication. That
is, an input sequence is multiplied by each of the weights ofquery/key/value to get query/key/value, respectively. There-fore numerous matrix multiplications are performed. Then,
the attention output is forwarded to feedforward networks (FC-
GeLU [ 3]-FC-dropout-Layer Norm [ 5]). Moreover, the output
of a feedforward network is transmitted to the upper encoder
layer as an input. These processes are repeated until the upper-
most encoder layer sends the output of the last feedforward to
the classiﬁcation layer for ﬁnal results.
2.1. Analysis of memory bandwidth requirement and
memory access patterns in BERT
BERT-base with 110M parameters is a large-scale network
model which uses signiﬁcant computing resources during infer-
ence. Arithmetic intensity (FLOP/B) is a measure of ﬂoating-
point operations (FLOPs) performed by a given code section
relative to the amount of memory accesses (Bytes). We exam-
ine the memory bandwidth requirement and memory access
patterns prior to checking the arithmetic intensity of each layer.
We used PyTorch 1.2.0 as a reference framework, Intel Xeon
Gold 6138 processor (Skylake SP), and MRPC benchmark
of GLUE (General Language Understanding Evaluation [ 7])
datasets.

2.2. Analyzing the computational characteristics of BERT
We conduct a detailed analysis according to the layer type
in each encoder layer (Table 1) to check the computational
characteristics of BERT. Matrix-Matrix multiplication (Mat-
Mat mul) depends on the characteristics of the data used inthe calculation; it can be categorized into Mat-Mat mul (1)
which multiplies an input feature by weight, and Mat-Mat
mul (2) which multiplies an input feature by another input fea-
ture. Mat-Mat mul (1) includes a query/key/value calculation
( q_head/k_head/v_head ), ﬁnal attention output calcula-
tion ( p ost_attn_sc ) due to the multi-head concept improv-
ing the performance of the attention layer [ 6], and feedforward
FC (FC1, 2) calculation. Mat-Mat mul (2) includes the calcu-
lation of attention score ( attn_sc ) multiplying a query by key
and attention output ( attn_o ) multiplying a softmax’s result
by value. Normalization includes layer norms (LN1 and LN2)
whereas the others include GeLU and soft-max.
In general, Mat-Mat mul is a compute-intensive operation
with a large number of data reuses. Mat-Mat mul (1) is a
typical compute-intensive operation that utilizes cache well,
and it turns out to have a large FLOP/B. Mat-Mat mul (2), on
the other hand, multiplies two input features together. In this
case, the computational dimension is smaller than Mat-MatMat-Mat mul (1)

3.1. XLNet introduction

ing the AR language model released after BERT. Similar to
BERT, XLNet uses the encoder side of Transformer consisting

It provides a superior performance compared to BERT on

In the training process, permutation method, as shown in
Figure 4, ﬁrst shufﬂes the input tokens, and then predicts
words for training according to the AR method. It enables
the model to consider bidirectional information. For example,
when shufﬂing the tokens of the input sequence and predicting
‘x5’ in permutation AR, as shown in Figure 4, the model
can consider ‘x6, x8’ tokens that are initially on the other
side. However, the method makes tokens to lose their original
position information. XLNet model solves this problem bya target position-aware representation which uses position
information according to the target index detailed in [8].
Besides, XLNet uses the key ideas of Transformer-XL [ 1]
for effectively learning long sentences. It learns data as a
segment unit divided from a long sentence. At the same time,
it uses the states of previous segments. Although it makesthe model learn long sentences effectively, it causes another
position issue. For example, each segment using an absolute
positional encoding method like BERT has the same position
information in a long sentence, as shown in Figure 5. Eachtoken in each segment should have different position infor-
mation. XLNet uses a relative positional encoding method
detailed in [ 8] to solve the problem that is more complicated
compared to Transformer-XL.
3.2. Comparison between BERT and XLNet
XLNet also has two types of multiplications which multiply
input feature by weight (Mat-Mat mul (1)) and an input feature
by another input feature (Mat-Mat mul (2)). Compared to
BERT, Mat-Mat mul (1) includes a relative key ( k_head_r )
calculation additionally. The result is used for the calculation
of a position score as an input. Mat-Mat mul (2) includes
additional multiplications for the calculation of position score
and segment score which respectively multiplies a relative key
by a query and a segment by the query.

4. Conclusion
In this paper, we have compared BERT and XLNet from the
perspective of computational characteristics during inference.
Through evaluation, we observed that both models exhibit sim-
ilar computational characteristics. Most popular operations
are Mat-Mat mul, which takes up most of the execution time
of the both models. Mat-Mat mul, which depends on the char-
acteristics of the data used in the calculation, can be divided
into Mat-Mat mul (1) multiplying an input feature by weight,
and Mat-Mat mul (2) multiplying an input feature by another
input feature. Mat-Mat mul (1) is a typical compute-intensive
operation that fully utilizes the cache, so Mat-Mat mul (1) has
a large FLOP/B. Mat-Mat mul (2) has a smaller input feature
than Mat-Mat mul (1), and the input feature is used only once
in Mat-Mat mul (2). It leads to higher memory bandwidth
requirement and low FLOP/B compared to Mat-Mat mul (1).
Also, XLNet exhibits a better benchmark score at the cost of
1.2×through additional target position-aware representation
and relative position encoding features.

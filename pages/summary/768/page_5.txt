### Overview of the Process Graph Stage

The process graph stage involves multiple steps including DMA Load, Kernel Computation, DMA Read, and Reformat Output. Steps 1, 2, 9, and 10 overlap with FPGA-related tasks, with overall performance dictated by the stage with the longest latency. To enhance performance, the communication and computation processes of the FPGA are fully pipelined, encompassing steps 3 to 7. This second level of pipelining allows for a batch of images to be sent to the FPGA, with the additional latency from batch processing mitigated by the first level of the pipeline. Once the FPGA completes processing, results are sent back to TensorFlow, where non-CNN computations are executed in parallel across all images. The optimized data movement steps overlap with kernel computation, thus amortizing the latency for non-CNN computations. This technique of deep software and hardware pipelining is also referenced in prior works.

### FlexCNN Compilation System

The FlexCNN compilation system, as illustrated, consists of three modules: the design space exploration engine, the instruction generator, and the integrator.

1. **Design Space Exploration Engine**: This module takes a CNN network description file from TensorFlow and available FPGA resources to determine optimal hardware configuration parameters, which are then used to generate the accelerator.

2. **Instruction Generator**: This generator processes the CNN network description and hardware description files to create instructions for each CNN layer. Non-convolutional layers are fused with adjacent convolutional layers to enhance computation efficiency. Each instruction generated is a VLIW-like format that includes enable signals, layer configurations, and tiling factors.

3. **Integrator**: The integrator incorporates the FPGA accelerator into the TensorFlow framework to perform end-to-end processing tasks, with optimizations discussed in a previous section.

### Experimental Results

The FlexCNN architecture is implemented using Vivado HLS on a Xilinx Virtex Ultrascale+ VCU1525 platform. The OpenPose-V2 network is utilized for testing, configured to handle RGB images of size 384x384 with floating-point precision. The FPGA design employs two DDR banks, allocating feature maps and weights to separate banks, with all architecture choices being parameterizable.

The optimal configurations identified for OpenPose-V2 include an 8x8 systolic array for the convolution module with a SIMD factor of 8. The configurations yield specific frequency and resource utilization metrics. Dynamic tiling and data layout transformations enhance performance significantly, demonstrating a 2.3x increase in efficiency. The DSP efficiency is also evaluated, revealing that 78.7% of DSPs are utilized effectively in the convolution layer. 

This comprehensive optimization strategy results in substantial performance gains, underscoring the effectiveness of the proposed FlexCNN architecture in FPGA implementations.

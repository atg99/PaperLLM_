The paper discusses the operation of a Cloud-Fog computing system, highlighting the interaction between mobile users, fog nodes, fog brokers, and cloud nodes. The process begins with mobile users sending job requests that are subsequently decomposed into smaller, independent tasks for processing within the Cloud-Fog infrastructure.

The problem formulation focuses on how requests from Internet of Things (IoT) applications are handled by the Fog layer, which breaks them down into tasks characterized by their instruction count, memory requirement, and input/output file sizes. The tasks are represented as T = {T1, T2, ..., Tn}, where n denotes the number of independent tasks.

The computing infrastructure comprises both cloud nodes and fog nodes, which share similar attributes such as CPU rate and usage fees, although cloud nodes are generally more powerful and costly. The entire set of processing nodes is represented as N = {N1, N2, ..., Nm}, where m is the total number of nodes.

Each task Tk is assigned to a processor Ni, leading to the formulation of task scheduling as a search for a set of node tasks. The execution time (EXT) required for a node Ni to complete all assigned tasks is calculated based on the execution time of each task and the CPU rate of the node. This is expressed mathematically, indicating that the execution time of each task Tk on node Ni is determined by its length and the node's CPU rate.

The overall goal is to optimize task scheduling within the Cloud-Fog environment to improve efficiency and reduce costs.
